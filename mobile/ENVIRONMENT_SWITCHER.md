# 应用内环境切换功能

## 概述

应用现在支持在运行时切换不同的环境配置，无需重新构建或重启应用。

## 功能特点

- ✅ **运行时切换**：在应用内直接切换环境，无需重启
- ✅ **配置持久化**：选择的环境会保存，下次启动自动使用
- ✅ **实时生效**：切换后立即生效，所有 API 请求使用新环境
- ✅ **可视化界面**：设置页面提供友好的环境选择界面

## 可用环境

### 1. 开发环境 (development)
- **名称**：开发环境
- **API 地址**：`http://10.0.2.2:4000`
- **描述**：本地开发服务器（Android 模拟器）
- **用途**：本地开发和测试

### 2. 预览环境 (preview)
- **名称**：预览环境
- **API 地址**：`https://c-api.kxf.ca`
- **描述**：生产 API 服务器（用于测试）
- **用途**：使用生产 API 进行测试

### 3. 生产环境 (production)
- **名称**：生产环境
- **API 地址**：`https://c-api.kxf.ca`
- **描述**：生产 API 服务器
- **用途**：生产环境使用

## 如何使用

### 方法 1：通过设置页面

1. **打开应用**
2. **进入设置页面**：
   - 在首页点击"设置"卡片
   - 或通过底部导航栏的"设置"标签
3. **选择环境**：
   - 查看当前环境（蓝色高亮显示）
   - 点击其他环境进行切换
4. **确认切换**：
   - 系统会提示环境已切换
   - 建议重新登录以使用新环境

### 方法 2：通过首页设置入口

在首页的功能列表中，点击"设置"卡片即可进入设置页面。

## 工作原理

### 1. 环境配置存储

用户选择的环境保存在 `AsyncStorage` 中，键名为 `app_environment`。

### 2. API 服务动态更新

- API 服务会定期检查环境配置（每2秒）
- 每次 API 请求前也会检查环境是否变化
- 如果环境变化，自动更新 `baseURL`

### 3. 配置优先级

1. **用户选择的环境**（保存在 AsyncStorage）
2. **编译时的环境变量**（`.env` 文件或 EAS 环境变量）
3. **代码默认值**（根据 `__DEV__` 和平台选择）

## 技术实现

### 核心文件

1. **`src/config/environments.ts`** - 环境配置定义
2. **`src/hooks/useEnvironment.ts`** - 环境管理 Hook
3. **`src/services/api.ts`** - API 服务（支持动态环境切换）
4. **`src/screens/main/SettingsScreen.tsx`** - 设置页面

### 环境切换流程

```
用户选择环境
    ↓
保存到 AsyncStorage
    ↓
触发 API 服务更新
    ↓
更新 axios baseURL
    ↓
后续请求使用新环境
```

## 注意事项

### 1. 切换环境后建议重新登录

切换环境后，建议：
- 退出当前登录
- 重新登录
- 确保使用新环境的认证系统

### 2. Token 可能无效

不同环境使用不同的后端服务，Token 可能不通用。切换环境后可能需要重新登录。

### 3. 数据不会自动同步

切换环境后，之前环境的数据不会自动同步。需要重新加载数据。

### 4. 开发模式显示

在开发模式下，登录页面会显示当前使用的环境配置，方便调试。

## 使用场景

### 场景 1：本地开发测试

1. 选择"开发环境"
2. 连接到本地后端服务
3. 进行开发和调试

### 场景 2：测试生产 API

1. 选择"预览环境"或"生产环境"
2. 使用生产 API 进行测试
3. 验证功能是否正常

### 场景 3：多环境切换

1. 在不同环境间快速切换
2. 测试不同环境的兼容性
3. 验证功能在不同环境下的表现

## 故障排查

### 问题：切换环境后 API 请求失败

**可能原因**：
- 新环境的服务器不可访问
- Token 在新环境中无效
- 网络连接问题

**解决方案**：
1. 检查网络连接
2. 重新登录获取新 Token
3. 查看控制台日志确认 API 地址

### 问题：环境切换不生效

**可能原因**：
- AsyncStorage 保存失败
- API 服务未正确更新

**解决方案**：
1. 检查控制台日志
2. 重新打开设置页面
3. 确认环境已保存

### 问题：设置页面不显示

**解决方案**：
1. 检查导航配置是否正确
2. 确认 `SettingsScreen` 已正确导入
3. 查看控制台是否有错误
